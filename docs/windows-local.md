# Windows 双击启动

## 日常使用

1. 从 GitHub 下载最新项目 ZIP，先**全部解压**。不要在压缩包中直接运行。
2. 双击 `启动企业库系统.bat`，也可以双击英文名 `start.bat`，两者功能相同。
3. 首次启动会安装依赖，保持联网并等待。看到 `Ready` 后浏览器自动打开，登录即可录入企业和产品。

本地演示账号：管理员 `admin / admin123`，普通成员 `user / user123`。仅监听本机 `127.0.0.1`；双击启动不等于公网部署。

运行期间保持命令行窗口打开。关闭窗口，或按 `Ctrl+C` 并按提示确认，可停止服务。下次双击会使用原资料。已有服务时再次双击会打开同一个网站，不会另建一份资料库。启动准备中再次双击，会提示等待原窗口完成。

可给 BAT 创建桌面快捷方式；不要把 BAT 单独移到桌面。路径可以包含空格和中文，不需要管理员权限，也不调用 PowerShell。

## Python 和依赖

支持 Python **3.9–3.13**，不限定 3.12。优先复用项目 `.venv`，随后查找指定 Python、已激活 Conda、常见 Conda 安装目录、Windows Python Launcher 和 PATH 中的 Python。

在项目内自动建立独立 `.venv`，按 `requirements.txt` 安装和检查所有适用依赖，包括 `Flask-Limiter`、`Flask-WTF` 和 Windows 时区包。不修改 Conda `base` 中的包；Gunicorn 只用于 Linux 网站部署，Windows 无需安装。依赖齐全后再次启动不需要下载。

## 更新项目并保留资料

1. 在旧系统的「备份」页面下载完整资料包，另存一份；然后关闭服务窗口。
2. 将新版 ZIP 的**源代码**覆盖到原来的项目根目录。不要把新版再套一层目录后从新目录启动，否则新目录会使用自己的空资料库。
3. 保留旧目录中的 `trade_agent.db`、`uploads/`、`backups/`、`.secret_key`。若已有 SQLite `-wal` / `-shm` 文件，也不要自行删除。使用自定义 `TRADE_DATA_DIR` 时保持该设置不变。
4. 双击新版 BAT。必须同时更新 `launch_local.py`、`requirements.txt` 及其他源代码，不能只换启动脚本。

自动准备环境只处理 `.venv`，不会清空业务资料。自动备份仍需另存到独立设备，避免电脑磁盘损坏时一起丢失。

## 常见问题

| 提示 / 情况 | 处理方法 |
| --- | --- |
| 仍提示必须 Python 3.12，或出现 `cutionPolicy` 错误 | 运行的仍是旧 BAT。完整更新源码，再从原项目目录双击新版 BAT。 |
| 找不到兼容 Python | 安装 Python 3.13，勾选「Add python.exe to PATH」。已装 Conda 但位于自定义目录时，可按下方方法指定其 Python。 |
| 下载依赖失败 | 查看窗口中 pip 的具体错误，恢复网络或修正单位要求的代理 / 证书配置后重试。安装完成前不会启动网页；不要关闭 TLS 校验。 |
| `.venv` 不可用 / 属于旧 Python | 关闭启动窗口，将项目中的 **`.venv` 文件夹**重命名为 `.venv.old`，再双击重建。只改环境目录，不要改名或删除数据库、附件。 |
| 端口被其他程序占用 | 关闭占用端口的程序，或在项目目录命令行执行 `start.bat --port 5001`。启动器不会结束其他程序。 |
| 网页没有自动打开 | 查看窗口是否出现 `Ready`；出现后手动打开窗口里显示的网址。不要在仍安装依赖时打开网页。 |
| 新版本启动后资料列表为空 | 先关闭窗口，确认是否从另一个解压目录启动。回到原来包含 `trade_agent.db` 的目录更新并启动；不要覆盖旧数据库。 |

自定义 Conda 路径可以在项目目录新建 `本机启动.bat`，内容如下（替换 Python 路径）：

```bat
@echo off
set "TRADE_PYTHON=D:\YourConda\python.exe"
call "%~dp0start.bat"
```

这不是必需步骤；常见安装位置会自动识别。此文件仅留在本机即可。

开发检查：`start.bat --check` 仅准备环境；`--no-browser` 不打开浏览器；自动化测试可设置 `TRADE_LAUNCHER_NO_PAUSE=1` 关闭退出时的按键等待。
